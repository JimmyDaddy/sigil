# Desktop 输入与排队正文约定

主输入区以 Markdown 原文作为发送与草稿正文，安全预览只派生显示。实时预览的完整文档沿用现有 fence 修复和 SafeMarkdown 渲染，不先构建只供流式使用的分块投影；完整正文不会因此截断。流式消息仍使用原有稳定前缀投影，HTML、链接、数学与 Mermaid 的安全边界不变。

建议打开时，Tab 或不带 Shift 的 Enter 选择建议；Shift+Tab 始终保留向前一个控件移焦的行为，不执行建议中的命令。组合输入 guard 仍先于建议与发送，主输入的 Enter 发送、Shift+Enter 换行约定不变。

排队消息的替换只用 trim 判断是否为空，实际提交用户输入的原始字符串，保留 Markdown 首行缩进、首尾换行和行末空格。完整安全正文可以预填；脱敏、截断或仅进程内材料仍要求用户完整重新输入，不拿预览补造原文。保存失败继续保留正在编辑的文本。

队列弹层中的替换表单独立拥有自己的提交，主输入区仅处理本身的表单提交。替换不会顺带发送或入队主草稿；成功回执关闭替换表单，真实失败保留替换文本和原主草稿。该边界也适用于运行中等待审批时的长草稿，不改变队列 generation 校验、错误处理或重试资格。

组件回归分别覆盖反向焦点、正常 Tab、精确排队替换与空白拒绝、完整 Markdown 的有界整串编码次数、CRLF/fence/code 呈现与流式转换。原生输入法、WebKit 焦点与窗口几何仍由最终候选实机确认。

附件入口与格式、预览和展开编辑共用一行工具区，以图片图标显示并保留可访问名称、悬停说明和忙碌/禁用状态。实时预览复用消息的受控 Markdown 标题、段落、引用、任务列表与数学排版，独立保留预览高度限制和原文编辑区；该呈现不会重挂编辑器或改写正文。

展开编辑使用当前会话列的剩余高度，短窗口不再以接近默认高度的独立视口比例限制源文和预览。仅含空占位的历史区暂时收起，有历史、加载重试、缺口提示或任务控件时仍保留可滚动的简短阅读区；收起编辑恢复原布局。源文与预览共享一个有限高度：宽区并排，窄区上下均分，各自内部滚动；编辑工具、收起和发送区保留在正文之外，额外附件等内容超出可用空间时可滚动到达。展开后的建议列表显示在正文区域内并受其高度限制，不再定位到整个输入区的上方。审批出现时暂停扩大布局，继续使用原有源文和预览高度限制（88px，窄区预览60px），审批结束再恢复用户已选择的展开状态。

在展开的源文、预览或输入工具区按 Escape 收起，并把焦点返回同一源文编辑器，保留选区、撤销历史与正文。建议和已打开的弹层先消费 Escape；中文组合输入期间不处理收起。该按键只作用于输入区，不触发运行取消；Enter 发送、Shift+Enter 换行约定不变。组件测试验证实际挂载节点的布局/滚动约束与焦点状态；840×560 窗口的可见高度增益、窄区分配与控件可达性仍需原生 WebView 复验。
