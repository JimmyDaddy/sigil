# Desktop 会话恢复与展示标题

打开已有会话只使用目录提供的精确 `sessionRef`、持久 `sessionId` 和必要的恢复绑定。
目录标题、最近会话偏好的 label 只用于界面展示，不再作为打开请求中的可选 label 回传。
这样，多行 Markdown 或含换行的旧标题仍可展示，不会因 label 的输入校验阻断已有会话。
新建会话、显式重命名以及 Rust 入口的身份、权限和 label 校验保持原有约束。

工作区启动恢复失败时，不删除原来的最近会话身份，也不把会话显示为已经打开。
主区域说明会话不可用；只有既有 `routeRecovery` 或 `recoveryActions` 允许时才提供手动重试。
未带恢复动作的旧错误保留显式重试兼容行为。重试仍走同一个精确打开入口，携带服务端
给出的非空 attachment 恢复绑定，不自动循环，也不自行产生或修改该绑定。
用户可以按允许动作进入会话库，选择其他会话或新建会话；成功选择后更新最近会话记录。
传输失败、未知拒绝、权限不足和真实缺失都不能被前端改写成成功；当前通用拒绝 DTO
没有区分缺失与权限原因时，界面保留失败事实，不从错误文案或目录第一页猜测原因。
手动重试再次遇到可恢复错误时，过滤结果或目录第一页没有该会话，不会清除其精确
身份和重试动作；再次重试使用服务端最新返回的恢复绑定。只有同一 `sessionRef`
实际返回了非 ready 状态或不同持久身份，才显示来源已变化并停止重试。

直接 App 回归使用 C11 自有目录中 159B、含两个换行的确切标题，覆盖从列表打开、
启动恢复、再次打开、展示标题保留、错误后保留身份、手动重试和不允许恢复的状态。
既有新建、重命名、过滤和草稿恢复用例继续验证。前端测试证明的是界面与桥接调用契约；
新候选仍需实机打开原多行标题会话，再正常退出和启动，确认恢复结果。

C12 首次启动曾回到“选择会话”，但没有保存此前 MRU 和当次 IPC 错误回执，
不能把它直接记作已捕获的 `session_label_invalid`。本次缺口由源码、目录元数据
及隔离回归共同确定。读取活跃 SQLite 时应包含 WAL；忽略 WAL 的 `immutable=1`
旧快照不得作为当前偏好事实，也不据此推断草稿丢失。
