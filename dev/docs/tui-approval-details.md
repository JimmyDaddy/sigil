# TUI 审批完整详情

2026-10-23。内部 `sigil-tui-host` 的审批保持默认简洁预览；`M` 打开同一待决请求的完整详情页，不改变其授权身份、默认动作或可用范围。

详情正文逐项展示完整 policy、summary、effects、containment、分析状态及全部分析原因、每个 subject 的原始/归一化/可用 canonical 路径、全部决定原因及说明，以及原有会话授权、来源 agent、change set、格式检查、恢复提示和命令族信息。正文按终端列宽折行，既有有界首屏摘要不会作为全文来源，也不再对详情裁掉尾部或只取前几项。权限判定与工具分析提供的原始安全边界继续生效。

完整详情页独立保留滚动位置。`↑↓`、`PageUp/PageDown`、`Home/End` 或正文滚轮浏览；`M` / `Esc` 返回原预览及其滚动位置，再次 `Esc` 才收起审批回到输入。查看全文不会打开通用 F4 详情，也不会放开待决 attention guard。新待决请求从简洁预览开始，不继承上个请求的详情位置。

决定按钮始终固定在底部，窄窗按完整按钮换行，鼠标命中与实际按钮使用同一几何。`Tab` / 左右键切换动作，`Enter` 执行当前选项；`Y` 允许一次，`N` 拒绝。进入详情不会取消这些已公开的决定键，也不会自动做出决定。会话允许、命令族允许只在原 authority 明确提供时出现，仍绑定当前 call/request 身份。详情页隐藏的 diff/hunk/file 控件没有鼠标命中目标；相关导航键在该页不改变背后的预览。

80×12 短窗先为底部决定和键位提示留出固定空间，预览与详情共用同一布局预算；取消短窗头尾的空白 padding，并在宽度足够时把动作选择和快捷决定合并为一行提示。默认预览仍显示风险、完整详情入口及可滚动正文，不自动跳转详情。diff 的摘要最多使用正文剩余空间，至少保留一行实际 diff；详情页可在 `End` 后同屏读完跨行的末字段。恢复到较高窗口后继续使用同一待决请求、默认动作、草稿及各自滚动位置。

状态与 TestBackend 回归应验证超过旧摘要上限的原因/subjects、长 summary 的末尾、80×24 与短窗滚动、固定决定与返回提示、两种滚动位置往返、旧请求到新请求重置，以及决定动作的精确身份。短窗回归须覆盖 `AppState → build_surface_model → render_surface` 的生产路径，不能只构造已经进入详情的局部 view。真实终端/cua-driver 资格化另记候选与截图，不用局部测试代替实机通过。
