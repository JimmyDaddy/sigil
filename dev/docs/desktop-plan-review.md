# Desktop 完整计划审阅

“审查完整计划”展示当前计划 ID 与 hash 对应的不可变详情。详情含 `legacyMarkdown` 时，Desktop 将该字段完整交给既有安全 Markdown renderer，只读呈现计划首尾、列表、表格与代码；不从正文猜测步骤、路径、检查或执行权限，也不将正文发送成新消息。原始 HTML、远程图片与链接继续受原有渲染边界限制。

这种详情不显示空结构列表、零计数徽标或内部结构化占位备注。结构化计划继续展示真实步骤、目标路径、建议检查、风险与备注。计划决定仍仅来自现有 `allowedActions`，沿用原 ID/hash、错误与审批流程；详情不匹配当前身份时不会显示旧计划正文。

组件回归验证完整首尾、代码空白、只读与安全呈现、结构化内容及决定状态。原生完整计划审阅仍需在最终候选上验证，不以组件测试代替。

短窗中，计划标题、风险、候选正文与完整详情在同一个可聚焦滚动区内；“审查完整计划”和当前允许的决定操作位于不随正文滚动的底部操作区，窄宽时换行排列。打开同身份的完整详情后，焦点移入正文，PageDown、Home、End 由浏览器执行滚动；同一计划的后续重投影不会反复抢走操作按钮焦点。计划加载或决定失败仍在操作区显示，忙态与 ID/hash 校验不变。

组件回归覆盖 320px、840×560 与宽窗的真实样式分支、完整长文及焦点/键盘默认行为。JSDOM 不提供像素排版与真实键盘滚动，840×560 下按钮可见及正文首尾可达仍须最终原生候选复验，不用组件检查代替。
