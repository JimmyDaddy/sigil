# Desktop 设置草稿与会话库确认流程

## 设置返回位置

从诊断或会话返回设置时，恢复离开时的分类、内容滚动位置与仍然存在的入口控件焦点。不同工作区分别记忆，最多保留最近 16 个工作区的导航状态，仅存于当前应用进程；不包含表单值或凭证。首次进入设置不额外移动焦点，原入口已经消失或不可用时也不强制改聚焦其他控件。

分类切换仍回到该分类的顶部，不改变现有草稿、保存和订阅语义。

## 读取失败与重新检查

连接清单区分别显示正在加载、可用与读取失败。失败时可在本区直接重试，不把错误显示成持续加载。清单尚未就绪时隐藏依赖它的默认模型区；重试成功后恢复模型设置，避免误导用户重新添加连接。已有连接缺少或无法读取凭证时，可通过相邻的“更新凭证”修复原连接，详情见[既有连接凭证修复](desktop-provider-credential-repair.md)；无效配置继续使用明确的配置诊断和替换流程。

更新状态首次读取失败时，设置页保留“重试”入口，只重新读取状态，不触发检查版本、下载、安装或重启。支持诊断提供“重新检查”；刷新期间保留当前工作区的上次结果，失败时说明仍显示旧结果。切换工作区后，旧结果与迟到回执不能覆盖新工作区的诊断。

## 上下文大小草稿

“设置 → 连接与模型”的上下文大小仍需点击“保存”才写入配置。编辑后显示“未保存”，可点击“还原”放弃修改。分类往返、返回会话以及重新进入设置不会清除尚未提交的值，也不会触发自动保存。

草稿由 App 持有，仅保存在当前应用进程内，按工作区、连接和模型分别隔离。它不包含 Provider 凭证，不写入浏览器存储或会话历史；退出应用后不保留。刷新连接清单时保留有修改的草稿；还原采用当前已保存值。正整数代表显式上限，空值代表自动判断，无效值不能保存。

保存失败保留输入和“未保存”标记。保存完成只清除本次提交的同一范围和同一值；用户在旧保存完成前返回设置输入的新值不会被旧回执覆盖。

## 会话库批量操作

主工具栏保留搜索与筛选入口；Provider、来源状态与置顶条件按需展开，已应用条件在列表上方可见并可一次清除。只有提交后的搜索参与筛选，输入草稿不改变空态。零结果时在空态提供清除筛选并返回搜索框；空库直接显示尚无会话。

窄窗口按会话名称、状态与多选组织列表，将 Provider、活动数量和更新时间放到名称下方，避免为固定表格宽度强制横向滚动。多选与批量操作保持可用，确认弹层继续展示全部目标和精确身份。

勾选记录后，分别发起删除可用会话、隔离不可用来源或删除不可用来源。预览弹层根据后端返回的动作显示具体标题、影响和确认按钮，默认聚焦“取消”。取消或 Escape 不执行操作。

确认框列出计划内的全部目标，包括可执行和受阻项目。名称、模型和时间来自发起预览时的展示快照；同名或没有名称的记录直接显示来源标识，其余记录可展开查看。长名单在弹层内滚动，清单刷新不替换已预览的展示快照。跨工作区切换会卸载原工作区的会话库及其预览。

展示名称不参与授权。确认仍提交原 `planId`、typed action 和精确 items；后端继续校验计划、身份及互斥条件。全部受阻时确认按钮禁用，失效计划走原有错误和重新预览流程。

删除可用会话只删除本地会话历史，不撤销已经发生的文件、命令或远程操作。隔离保留来源以便手动恢复；删除不可用来源无法从隔离目录恢复。批量执行逐项处理，单项失败不掩盖其他结果。汇总先显示完成、失败、跳过数量，逐项状态和来源标识在“查看逐项处理结果”中可达。

活动数量使用“条消息 / 次工具结果”表达；工具结果数量不代表独立工具调用数量。意图页简介描述已确认的目标和相关改动，不将来源或防陈旧机制作为普通用户的入口说明，也不承诺任意副作用可撤销。

## 交互依据

确认框的动作、目标和取消入口参考 [W3C 数据错误预防说明](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html) 对重要提交审查与确认的原则，以及 [WAI-ARIA 确认弹层模式](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) 的标题、说明和模态语义。该引用是本流程的设计依据，不构成完整无障碍合规声明。

## 首次会话空状态

首次空库的主要引导只在主区显示，侧栏保留会话数量，不重复显示“没有匹配”或第二个开始入口。只有已经提交的搜索与已应用筛选才触发“没有匹配”的提示；尚未提交的搜索草稿不改变空态判断。加载、读取失败和来源警示保持各自状态。
