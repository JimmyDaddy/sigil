# Desktop 短窗口审批布局

当内容视口高度不超过 640px 且当前审批与编辑区共存时，会话区缩小外围间距与历史区留白，为审批正文和编辑底栏保留高度。审批标题、风险和决定区仍在正文滚动区之外；完整命令或 diff 在原有可聚焦正文区滚动，后续消息仍保留原编辑器与草稿。空闲或较高窗口继续使用原有布局。

组件回归覆盖真实审批区与编辑器的样式作用域、固定决定区结构、完整正文尾部、草稿与编辑器身份；JSDOM 不提供像素布局，该测试不宣称窗口几何通过。840×560 原生窗口的底栏可见性与键盘审阅由最终候选实机验收。

审批正文先展示完整实际动作，再展示摘要与分析说明。对 typed 命令操作，仅在冻结预览严格符合内置命令的四行环境格式时，将完整命令原样放在正文首部，并把工作目录、shell、终端模式与运行期限收进可展开的“执行环境”。外部目录授权目标仍完整常显；未知格式、多重命令标记或路径换行歧义保留整份冻结正文，不从工具参数补造命令，也不截断或重算摘要。风险、授权范围说明与诊断继续可达，决定按钮与原审批 guard 不变。

完整命令提供带名称的只读多行文本语义，正文初始焦点和 Escape 返回输入框沿用原行为；同一审批快照不抢焦点，也不重置已展开的环境。组件测试只证明文本、语义与单一正文滚动结构，WebKit AX 实际取值和窄窗逐页审阅仍需最终候选原生验证。
