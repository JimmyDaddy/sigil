# Desktop 提问表单展示与本地验证

当请求仅含一个问题，且请求标题与该问题的文字完全相同时，Desktop 只显示一次标题。字段分组的 legend 保留为屏幕阅读器可读的名称，输入控件也保留完整标签。不同标题及多问题请求继续显示各自的上下文；不解析、改写或翻译模型提供的问题、描述和选项。

必填问题未回答，或必填单选的“其他”尚未填写时，表单先在本地阻止提交。验证状态保存问题类型和原始标签，由当前界面语言生成提示；下拉占位、“其他”选项及其输入名称同样支持中英文。切换语言不会清空答案。服务端决定失败仍走原有错误分支，不通过匹配错误文字做翻译。

成功提交仍使用原 question ID、选项 ID 和原始答案，保留中文与首尾空白；可选空答案仍省略。请求身份变化后的草稿重置、允许动作、忙态、拒绝、取消及已保存回答的恢复流程保持原有契约。本批不修改 IPC、持久化或执行权限。

提交答案后，成功回执中的 `continuationRunId` 只绑定当前会话和原问题身份。继续运行所带的内部启动说明不再显示成新的用户气泡；无论启动事件先到还是回执先到，都只停止呈现该 run 的临时用户展示槽。真实持久用户消息、其他运行、工具结算中的答案和最终回复仍保留。回执身份不符、传输结果不确定，或切换会话后旧回执晚到时，不据此隐藏消息。这里不根据提示文案判断来源，也不改变后台运行和历史记录。

组件回归覆盖中英文必填单选、自由文本、多选、“其他”、相同与不同标题、多问题上下文、语言切换及答案原文；直接集成回归覆盖继续回执与事件的两种顺序、同文案持久消息、其他 run、答案结果查看、不符与不确定回执及会话切换。组件测试不等同于原生 WebView 的布局或辅助技术验收；真实短窗表单仍需绑定新候选复验。

已回答后的卡片按 typed 状态收敛：`decision_accepted` 以简短“回答已保存”提示和原有继续动作呈现；`continuation_claimed` / `continuation_started` 显示中性的“已收到回答，正在继续…”。此时不再显示需要输入的大标题、提问用途徽标、嵌套恢复框或内部 question ID。原始问题仍作为区域的无障碍名称，未回答时的完整表单、字段标签和原文校验保持不变。继续失败仍明确提示；待继续状态保留已有继续／重试按钮，已经开始的状态不新增重复继续动作。问题队列的前后导航和忙态禁用规则不变；不从 ID 生成答案，也不改写答案结果、回执、IPC 或持久化。
